Publishing is the manual `release-v5` workflow (`.github/workflows/release-v5.yaml`) run from `v5` after this merges. It stages each package whose local version is ahead of npm. Nothing from the v5 line moves `latest`. See the [changelog README](./README.md).

Versions were applied with Changesets (`pnpm exec changeset version`). Per-package notes are in each package's `CHANGELOG.md`. The release script still refuses any version `>= 6.0.0`.

## API compatibility

Checked against `41df0440`:

- `packages/keyv/src` is unchanged. `Keyv`, `KeyvOptions`, `KeyvStoreAdapter`, hooks, events, and `get` / `set` / `delete` / `clear` / `has` / `iterator` are the same.
- `KeyvRedis` still implements `KeyvStoreAdapter`. `createKeyv` / `createKeyvNonBlocking` are unchanged. Clients **created by** `KeyvRedis` keep v5 defaults on top of `@redis/client` 6: RESP 2, no command timeout, and a 5 second TCP keepalive, including cluster node clients built from `defaults.commandOptions`. A client you pass in is not rewritten. The hookified v1 `(event, handler)` hook methods still work.
- `BigMap` `Map` methods and `createKeyv` are unchanged. hookified v1 `logger` and `throwHookErrors` still work, including the `(event, handler)` hook methods and `onHookEntry`. `emit("error")` with no listeners does not throw. `Hashery` is still re-exported; its hash API is unchanged. Hookified v1 option names on that re-export follow hashery 3 (`eventLogger`, `throwOnHookError`).
- `KeyvGzip` `Options` still accepts pako v2 `to: "string"`. `decompress` still returns a string. `compress` returns a `Buffer`, which is a `Uint8Array`.
- `defaultSerialize` / `defaultDeserialize` keep their signatures. A plain `Uint8Array` is now stored as `:base64:`, and old byte objects still deserialize.
- `@keyv/valkey`, `@keyv/dynamo`, `@keyv/mongo`, `@keyv/mysql`, and `@keyv/postgres` adapter source is unchanged and still typechecks against the upgraded drivers.

`@keyv/redis` and `@keyv/bigmap` set `engines.node` to `>= 22.18` because `hookified` 3 does. Node.js 20 was already end of life (2026-04-30). That engine floor is a minor, same as `@keyv/sqlite` 4.1.0 when it left Node.js 18.

## @keyv/redis@5.2.0

- Duplicate event listeners after reconnect (#2106).
- Concurrent operations dropped while connect was in flight (#2107).
- `@redis/client` 6 and `hookified` 3, with the v5 client defaults above, including cluster node clients.
- hookified v1 `(event, handler)` calls, `onHookEntry`, and `getHooks` returning handler functions.
- Re-exported `createClient`, `createCluster`, and `createSentinel` follow `@redis/client` 6. Use `KeyvRedis` or `createKeyv` when you want the v5 defaults.

## @keyv/bigmap@1.4.0

- `hashery` 3 and `hookified` 3.
- Node.js `>= 22.18`.
- v1 `logger` / `throwHookErrors` names kept, plus the v1 `(event, handler)` hook methods. `Hashery` is still re-exported. Its hash API is unchanged. Hookified v1 option names on that re-export follow hashery 3.

## @keyv/compress-gzip@2.0.4

- Compressed values are stored as base64 instead of index-keyed byte objects (#2009). Legacy values still read.
- `pako` 3. `to: "string"` remains a valid option.

## @keyv/serialize@1.1.2

- Plain `Uint8Array` values serialize as `:base64:` before `toJSON`. `Buffer` behavior is unchanged.
